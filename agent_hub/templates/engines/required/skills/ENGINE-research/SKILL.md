# {label} research

Run the process card [references/process/research-note.md](references/process/research-note.md); each stage has a pattern card in `references/patterns/`.

## Source tiers

- **Tier 1**: shipped products in the field, played or captured; canonical books; conference talks with the real transcript. A rule can rest on tier 1 plus the project's own measurement.
- **Tier 2**: official docs and release notes, studio postmortems, engineering blogs.
- **Tier 3**: practitioner videos, forums, summaries written by a model. A proposal only, never a rule on its own.

## Rules

1. Read what the project already knows first. A lookup that repeats a known fact is waste.
2. Every claim cites title, author or speaker, URL or ISBN, date, and the page or timestamp. What you did not open (a search snippet, memory) is marked and never carries a recommendation alone.
3. Compare in one unit. Both sides of a band table use the same measure, taken the same way.
4. A note ends in a verdict someone can act on: which gap to close first, which owner, how to tell it closed.
5. You change no product file. Gate lines are drafts for the hub to adopt.
