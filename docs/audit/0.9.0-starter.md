# agent-hub 0.9.0 starter-instruction audit

Request: Auto Arkham direction #10596, founder #1321 ("what instructions does the starter carry, and can a fresh project's AI do the basic infra behaviours, and does it know the tower exists").
Date 2026-11-13. Method: PyPI wheel `dongduni-agent-hub==0.9.0` in a fresh venv, `dah init --hub claude --infra claude` in a blank non-game repo (a one-line README, "Bean Counter, a budgeting CLI"), Claude Code 2.1.322, `--setting-sources project` so none of the tester's own CLAUDE.md or skills leaked in. Nothing in agent-hub was changed. Transcripts: `docs/audit/0.9.0-starter-transcripts/`.

## Top finding

`dah init` writes **no CLAUDE.md and no AGENTS.md**. A session reads the protocol only when the tower opens it with "First read `.tower/lanes/<lane>.md` and `.tower/PROTOCOL.md`" (`engine.py:_read_first`), or when a person types `/dah-<lane>`. A plain `claude` opened in the project is a stock agent that has never heard of the tower (smoke B-1).

## 4. Game-specific leakage

A grep over every shipped template, guide, README and SETUP for Auto Arkham, Godot, Roam, Tripo, Blender, Mixamo, Steam, hero, character, story, world found **no game-only text**. The `animation` engine's "Story" and "Storyboard" are generic film terms. What a non-game project can still trip on, none of them game content:

1. `guide/SETUP.md` l.34: knowledge hints list "Roam" among MCP names. Harmless detection list, but reads as house-specific.
2. The `audit` lane defaults to model `fable` (`config.py` l.339, `install.py` l.67) and the `research` lane to `opus`. A person without those on their plan gets a lane that errors at the first session. No fallback is stated except in audit.md l.15 ("where Fable is not configured, Opus"), which I did not check the tool applies.
3. The lane names (`hub`, `infra`, `research`, `audit`) are generic. Game lane names live only in Auto Arkham's own repo.
4. The `/dah-<lane>` shim text and PROTOCOL use `skill("{skill}")` (research.md l.5) and call the folder `.agents/skills`. That is the Codex/OpenCode layout; Claude Code reads `.claude/skills`. Not game-specific, but a claude-runtime project does not get its research or audit skill loaded by name.

## 5. Fix list (ranked; nothing applied)

1. **Ship a project `CLAUDE.md` and `AGENTS.md` at init** (and through `dah update`), short: "this workspace runs agent-hub; the tower opens, closes and feeds lane sessions, never do that by hand; humans use the hub chat and the review board; you are a plain session unless `TOWER_LANE` is set; if it is set read `.tower/lanes/$TOWER_LANE.md` and `.tower/PROTOCOL.md` first; for a user request to the hub use `dah`". Fixes rows 1, 2 and the B-1 failure. Smallest change with the largest effect. Append to an existing file if there is one (never overwrite).
2. **Hub template: write the brief fields.** One paragraph in hub.md: every `dah task` brief carries `model:` and `effort:` (or `Line:`), `paths:`, `after:` when it depends on another task, and a `--deliverable` key when it reworks something; use research for questions and audit for process reviews; read `dah ratings` and `dah blame` at review. Fixes rows 3, 4, 5, 17, 18, 19.
3. **Engine flow in PROTOCOL or a skill the hub loads**: check the row's process and pattern card status; if not confirmed, `prepare` first; send-backs go through the revision rule. Today it exists only in `guide/ENGINES.md` and the Auto Arkham repo. Fixes rows 15, 16.
4. **Lane close-out section in team.md**: commit only your own files (never `git add -A`), remove temp dirs, say what `blocked` and `note` are for, handoff shape and "end the turn after", save memory where PROTOCOL l.65 says. Rows 7, 8, 9.
5. **Permissions block in PROTOCOL**: paid calls, deploys/publishes, secrets, and force-pushes go to the board as items; named for every lane, not only infra/hub. Rows 21-23.
6. **Install skills where Claude Code reads them**: write the research/audit skills to `.claude/skills/<name>/` when the lane runtime is claude (keep `.agents/skills` for Codex/OpenCode). Leakage item 4.
7. **Hub rule for decisions**: when a human answers an item the hub says "decide it or follow it, then close the item" (A-4 left item #1 open and had no way to know). Row 14.
8. **Say when to use live `ask`** on Claude Code (does the tower route it?) and when to post an item instead. Row 20.
9. **Model fallback**: `dah init` should check the models it names (`fable`, `opus`) and write a model the runtime accepts; or doc the failure. Leakage item 2.
10. Housekeeping: hub told to run `dah` commands alone, 2 of 12 broke it (a one-line reminder in hub.md); drop "Roam" from SETUP's hint list.
