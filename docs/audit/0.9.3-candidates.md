# agent-hub 0.9.3 candidates: what else to port from Auto Arkham

Request: Auto Arkham direction #10755, founder #1337 ("is there anything else to take from here? subagents, skills, base Claude instructions, shared instructions, useful infra such as the footer"). Audit only. Nothing is ported by this file.

Read for this audit: `.claude/agents/*`, `.opencode/plugin/*.ts`, `tools/tower/cc/*` (gates, pretool, urgent, settings, harness text), `tools/tower/*.py` (listed per row), `.opencode/skills/*` front matter and the neutral ones in full, `board.html` ids. Compared against agent-hub 0.9.2 by reading `agent_hub/*.py`, `templates/`, `docs/port-from-auto-arkham.md` and `docs/audit/0.9.1-starter.md`. Line counts are the source's. Where I say agent-hub "has" something, I found it in the 0.9.2 code; where I say it lacks something, a grep of `agent_hub/` and `templates/` found nothing.

Columns: **Neutral?** = works for a project with no game words: yes, cut (after removing named things), or no. **Effort** S (under a day, mostly copy and rename), M (a day or two with tests), L (several days, or needs a design choice). **Value** = for a new project in its first month. **Rec** = port now (0.9.3) / later / never.

Already in agent-hub, so not listed again: tower loop, rotation by handoff, nudges, memory guard (`memwatch.py`), light/heavy slots by `heavy_paths` (`engine.py` `_slots`), ntfy and desktop notify, usage bar, stats, ratings, engines, process and pattern cards, research and audit lanes, the Claude harness text (PROTOCOL.md, `docs/lane-harness-claude.md`), `.claude/skills`.

## Top 5 (my pick, in order)

1. **Gate pack as a Claude Code PreToolUse hook** (kill gate, git sweep gate, `.env` read gate, binary edit guard). The failures it prevents (a bad process kill that took down every lane tab; a `git stash` that lost another lane's edits; a 70 MB binary patch stored in session history) hit any multi-lane setup in week one, and the code is neutral and already tested.
2. **Four neutral subagents** (`explore`, `librarian`, `looker`, `general`) as `.claude/agents/` files: 40 lines in total, every project wants them, and the lane rules already point at them.
3. **Done gate, generalised** (a `done_gate` command in config; `report done` is refused until it passes on a clean worktree of HEAD) with the **scratch sweep** that deletes finished tasks' worktrees. It is the cheapest "a lane cannot say done on a red build" rule, and worktree leftovers filled the source's disk once (59 GB).
4. **Machine card and footer strip** (load, CPU, memory, swap graded green/amber/red against this machine's own cores and RAM, plus the usage footer). The board then explains why a task is not starting; the grading code is 91 lines.
5. **Urgent tell + API-error push.** The first lets the human stop a runaway lane mid-turn (a file injected at the lane's next tool call); the second turns "the lanes look idle" into "your login expired" on the phone.

## 7. Suggested 0.9.3 scope

- **Safety (S to M):** gate pack and PreToolUse runner with the `GateDeny` log; urgent tell; hook recorder and API-error push.
- **Starter content (S):** four subagents, `humanizer`, media-reading card, `review-board` skill, concurrent-session paragraph in PROTOCOL.md, two harness lines, `project-audit` recipe.
- **Board (M):** machine card, footer strip with optional Claude usage percent, done gate and scratch sweep as config keys.

Later: `qa` lane template, humanizer-ko/ja as options, `.claude/rules` loader, AGENTS.md scaffold, slot wrapper, liveness, memory-pressure admission, lane-cap card, night check as an extension pattern.

## 8. Risks to check before porting

- The gates' shell lexer is POSIX-only. Windows lanes need a PowerShell-aware variant or a stated "gates are POSIX only". Rename the protected-word list to dah's process names.
- The hook recorder writes under the workspace's `.tower` state per lane; sessions started without the tower have no hook, so liveness and API-error rows never see them (same as the source).
- The usage percent calls an undocumented Anthropic endpoint with the Claude Code OAuth token. Keep it read-only, optional, off by default; on failure show "unknown", never 0.
- The done gate runs a user command on a worktree: it needs a timeout and a memory ceiling, and the worktree must live outside the repo.
- One tested false positive in the source's own gate: a shell heredoc whose text merely contains kill-command words was refused as if it were a kill. The port should lex heredoc bodies as data.
